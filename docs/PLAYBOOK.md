# Плейбук на день хакатона

Документ для команды: что сделать до старта, как распределиться в первые часы и что показать жюри.

## До старта (можно готовить заранее)

- [ ] Все зарегистрированы на GitHub, один человек создал репозиторий и добавил остальных в **Collaborators** (Settings → Collaborators → Add people). Каждый принял приглашение.
- [ ] Репозиторий клонирован: `git clone <url>`, `cd <папка>`, `npm install`, `Copy-Item .env.example .env.local`.
- [ ] Проверено, что `npm run dev` открывается и демо-режим отвечает без ключей.
- [ ] Выбран хостинг (Render / Railway / Fly.io), репозиторий подключён, но деплой можно сделать в один клик.
- [ ] В Figma — минимальный UI-кит по токенам из `.stitch/DESIGN.md`: 2 цвета, 1 шрифт, кнопка, панель, поле ввода.
- [ ] В Google Slides — шаблон питча на 8 слайдов (структура ниже).
- [ ] Если правила хакатона запрещают код до объявления кейсов: храните наработки в личной копии и после старта перенесите в чистый конкурсный репозиторий (смотрите время первого коммита).

## Первые 30 минут после объявления кейса

1. Зафиксируйте кейс одной фразой: «Для [кого] мы делаем [что], чтобы [результат]».
2. Заполните `config/domain.ts`: название, описание, системный промпт, 5 быстрых промптов, название сущности.
3. Нарисуйте на бумаге 3 экрана и 3 действия агента. Не пишите код дольше 10 минут без проверки идеи.
4. Разделите роли:

| Роль | Отвечает за |
| --- | --- |
| Организатор | кейс, питч, тайминг, финальная демо-ветка |
| Промпт-инженер | `systemPrompt`, примеры диалогов, качество ответов |
| Fullstack | инструменты в `tools.ts`, данные, API, деплой |
| Демонстратор | сценарий показа, запасные данные, ответы на вопросы жюри |

## Что меняться в коде

- **Системный промпт и тексты интерфейса** — `config/domain.ts`.
- **Новый инструмент агента** — добавьте объект в массив `tools` в `lib/ai/tools.ts`:
  `name`, `description`, `parameters` (JSON Schema), `execute(args)`.
  После этого модель увидит его автоматически; вызов и результат появятся в трассировке.
- **Реальные данные** — замените функции в `lib/store.ts`, не меняя их сигнатуры.
- **Другой провайдер** — `.env.local`, переменная `AI_PROVIDER`.

## Быстрая проверка агента (smoke-тесты)

В демо-режиме (`AI_PROVIDER=mock`) введите в чат:

1. `Посчитай 12 * (7 + 3)` → ожидается вызов `calculator` и результат `120`.
2. `Создай задачу: подготовить демо` → вызов `add_item`, новая строка в таблице.
3. `Покажи все задачи` → вызов `list_items`, список в ответе.
4. `Найди идеи для кейса` → вызов `mock_search`.

Если на вкладке «Трассировка» вызовов нет — проверьте `AI_SUPPORTS_TOOLS` и поддержку function calling у модели.

## Питч на 8 слайдов

1. **Проблема** — одна боль конкретного пользователя.
2. **Решение** — агент и его 2–3 ключевых действия.
3. **Как это работает** — схема: пользователь → агент → инструменты → результат.
4. **Демо** — живой сценарий на 2 минуты (всегда имейте запасной сценарий и мок-данные).
5. **Почему ИИ-агент** — что именно модель делает лучше скрипта.
6. **Данные и инструменты** — откуда берём информацию, куда пишем результат.
7. **Метрики и монетизация** — 1–2 измеримых показателя.
8. **Команда и следующий шаг** — что сделали бы за неделю.

## Правила выживания

- Не коммитьте ключи, `.env.local`, `node_modules`, `dist`.
- Ветка под задачу, PR в `main`, перед новой задачей `git pull`.
- За 30 минут до дедлайна прекращать добавлять фичи и только проверять демо.
- Демо всегда открыто в браузере и задеплоено: жюри может попросить ссылку.
